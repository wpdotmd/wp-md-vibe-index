# Contributing to the vibe-code index

The scores on [wp.md/vibe-code](https://wp.md/vibe-code/) are editorial. Data
that nobody can inspect is just an assertion, so all of it lives here as one
JSON file per plugin, and the pull request is the whole interface — no forms,
no accounts.

Read [METHODOLOGY.md](METHODOLOGY.md) first. Most disagreements turn out to be
about the method rather than the number.

## What a good PR looks like

**One plugin per pull request.** Faster to review, easier to revert.

Edit `data/vibe/<slug>.json`. The slug must match the plugin's detail slug in
the premium ranking — if it doesn't, the record is ignored.

### Fields you may edit

| Field | Rules |
|---|---|
| `moat` | 0–100. The share that is *not* code you could commission. Justify it in the PR body. |
| `moatTags` | 1–4 from the taxonomy in METHODOLOGY.md, strongest first. |
| `build` | `sitting` \| `weekend` \| `weekends` \| `months`. MVP only, assuming a current coding agent. |
| `upkeepHoursPerYear` | Hours a year to keep your own version alive. Be honest; this number carries the whole money model. |
| `couldBuild` | One or two sentences: what an agent genuinely gets you. |
| `stillMissing` | One or two sentences: what you'd *not* have the day after. This is the most valuable field in the file. |
| `requirements` | 3–6 concrete bullets. They become the generated starter prompt, so write them as things you'd actually ask for. |
| `confidence` | `high` \| `medium` \| `low`. How sure the moat score is. Use `low` freely — a low-confidence score is more useful than a falsely certain one. |
| `alternatives` | Up to 6 free/OSS options that already do the job. Must be finished, installable, actually free, and genuinely replace the core job. For WordPress the honest answer is often the plugin's own free tier — say so. |
| `crossRef` | How other public indexes rate the same product. Include the disagreement *and why*, not just the link. |
| `notes` | Optional. Anything a reader should know that doesn't fit above. |
| `reviewedOn` | Set to today when you materially change a judgement. |

### Fields you may not edit

Everything under `derived`. Price, live-site count and `codeShare` are
regenerated by `wp ptp vibe_export` and your changes will be overwritten on the
next run. If a price is wrong, the fix belongs in the premium registry — open
an issue and say so.

`verdict` is also derived: it's a pure function of `moat` (see METHODOLOGY.md).
Argue about the score, not the label.

## What gets accepted

- **Corrections with a reason.** "Wordfence should be 88 not 60 because the
  product is the threat feed, not the firewall" is a great PR.
- **A missing plugin** that's in the tracked premium top 50 and that you can
  describe honestly, including the parts that make it hard to replace.
- **Better `stillMissing` prose.** Vague entries are the weakest part of this
  dataset.
- **Sharper `requirements`**, especially from someone who has actually tried
  to build the thing.

## What gets rejected

- Score changes with no argument attached.
- PRs from a vendor arguing their own moat up, or a competitor arguing it
  down, without disclosure. Disclose the conflict and the PR is still welcome;
  hide it and it isn't.
- Edits to `derived`.
- Anything that makes a `requirements` list into a feature-parity wishlist. The
  prompt is meant to produce a *usable MVP*, not a clone.
- Bulk PRs touching many files at once.

## House rules

Verdicts are independent of sponsorship. wp.md sells sponsor slots; sponsors
appear in a labelled rail and have no influence on any score here. If you spot
a score that looks like it was bought, say so publicly in an issue — that
accusation should be cheap to make and easy to check, which is the entire point
of this directory existing.

Conflicts of interest: the maintainer builds and sells WordPress themes and
plugins (WPZOOM). Where a scored product competes with his own, say so in the
PR and it'll be weighed accordingly.

## Validating your change

```bash
python3 -m json.tool data/vibe/<slug>.json > /dev/null && echo OK
```

Or, with the plugin installed:

```bash
wp ptp vibe_export --dir=/tmp/vibe-check
```

which regenerates every file and lets you diff for accidental damage.
